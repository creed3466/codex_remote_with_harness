# Engineering Discipline

- State assumptions when ambiguity matters; ask if blocked.
- Prefer the simplest implementation that satisfies the request.
- Do not add speculative features, abstractions, or configurability.
- Touch only files needed for the task.
- Match existing project style.
- Do not refactor adjacent code unless required.
- Remove only dead code created by your own change.
- Define verification for non-trivial changes.
- For bug fixes, prefer reproducing test, then fix.
- Every changed line should trace to the user's request.
